# SCORG v1.5 — Background reliability

## What changed

- The foreground watcher continues using the `specialUse` service type. This avoids using Android 15's time-limited `dataSync` service type for a long-running watcher.
- The watcher notification uses a new quiet, low-importance, no-vibration channel, a short title, no timestamp, ongoing flag, and alerts only once.
- Explicit user intent is stored in `WatcherPreferences`. A deliberate **Stop watching** clears it.
- Android's normal `START_STICKY` restart re-creates the observer and sorting callback when the system restarts the service. An unrequested sticky restart stops itself.
- While the app is visible, if the user previously enabled watching and the service has stopped, SCORG tries to restart it once (with a cooldown) when necessary permissions are still granted.
- A receiver attempts to resume an opted-in watcher following `BOOT_COMPLETED` or `MY_PACKAGE_REPLACED`, only when the OS permits foreground-service startup.
- Android 11+ process exit reasons, previous process exit status, and service uptime are recorded under Developer diagnostics.
- App information/battery settings shortcut and Xiaomi-specific guidance are provided in Developer diagnostics.

## Important limits

- Android 13+ can let users dismiss foreground-service notifications. `setOngoing(true)` is a request, not an absolute lock.
- Some OEMs kill processes aggressively. No Android API guarantees a third-party watcher will remain alive indefinitely.
- Starting a foreground service from the background is restricted by OS version, boot conditions and manufacturer policies. A failed attempt is logged and is not endlessly retried.
- An explicit Android **Stop**, force stop, or disabled app/permissions must not be circumvented. Reopening SCORG allows the user to restart watching.
- A low-importance notification may still be shown in a larger layout depending on OS skin and channel settings. Users can select Silent/Minimize in Android notification settings if available.
- Release APK signing must eventually use a proper long-lived signing key; stable CI debug signing is only for development.

## Manual test checklist

1. Update using a signed build from the canonical `diagnostic-screenshot-detection` branch.
2. Start watching; take a screenshot. Verify the sorting popup and move to a chosen folder.
3. Dismiss notification, dismiss from Recents; verify screenshot sorting after 5, 30, 60 minutes and several hours.
4. Open SCORG, expand **Developer diagnostics**, check **Previous process exit** and `Service.onCreate`/`onDestroy` events when the service has been stopped.
5. In SCORG tap **Stop watching**. Verify no further screenshot popup and that reopening SCORG does not automatically restart the watcher.
6. Tap **Start watching**; test a reboot. SCORG attempts restoration when the OS delivers the boot event and allows the start; otherwise opening the app should recover without losing enabled state.
7. Compare the new notification channel `Scorg · Silent watcher`; put it on **Silent** and **Minimize** in system settings where provided.
